# v0.5.0 QA Test Plan — Explicit Taste Preferences (REL-12)

**Scope:** seeded taste categories (0021), per-friend/per-category trust weights (0022), and the **casual 5-dot taste grid (IT-047, Phase 3)** — the only *frontend* surface shipped so far. Quant mode + toggle (IT-048/049, Phase 4), friend-profile tuning (IT-050, Phase 5), IT-110 (Phase 6) are **not built yet** — their sections below are placeholders to fill as they ship.
**Design record:** an override is a single nullable trust *weight* (`NULL`=no opinion, `0`=mute, `1..5`=ascending trust). See `workspace/v0.5.0-implementation-plan.md` decision record §2 and migration `0022` header. The invariant this QA must protect: **`NULL` ≠ `0`**, and the casual grid **never writes `0`**.

## How to run (Claude + Chrome plugin, deployed prod)

- **Precondition:** `main` deployed at commit `93a89a0` (Phase 3) and **hard-refreshed** (GitHub Pages CDN cache). Migrations `0021`/`0022` are already applied + verified in prod — no DB steps needed to deploy.
- Run against the deployed prod app signed in as your own account (the account must have at least one **accepted friend**; a couple of your own rated places make the personalized columns meaningful).
- **Debounce:** saves are debounced ~300 ms then written. After a tap, **wait ~1 s** before asserting persistence.
- **Native `confirm()` dialogs freeze automation** — none exist in the Phase 3 taste flow, but the regression pass (Part 7) hits Remove friend / delete: **Peter clicks those** by hand.
- **Authoritative DB check** (RLS-respecting, runs as *you*) — paste in the page's DevTools console:
  ```js
  await supabaseClient
    .from('friend_taste_overrides')
    .select('friend_id, category_id, weight')
    .order('updated_at', { ascending: false })
    .then(r => console.table(r.data))
  ```
  Returns only your own rows (own-row RLS). Use it wherever a step says "console check".

## Part 5 — NULL vs 0 invariant (critical) + clear = delete

| # | Steps | Expected |
|---|-------|----------|
| 5.1 | On a cell currently set to 3, tap **dot 3** again (the current level) | Cell clears to **0 filled dots** |
| 5.2 | Wait ~1 s → console check | **No row** exists for that `(friend, category)` — the row was **DELETEd**, not set to `weight = 0` |
| 5.3 | Scan the whole console result | **No casual-grid row has `weight = 0`** anywhere (casual mode must never write mute) |
| 5.4 | Reload → reopen Taste | Cleared cell is still empty; other set cells intact |
| 5.5 | (SQL editor cross-check, optional) `select weight, count(*) from public.friend_taste_overrides where rater_id = '<your-user-uuid>' group by 1;` | Only `NULL` (from quant mode, none yet) and `1..5` — **no `0`** from Phase 3 |

> Why this matters: if "cleared" ever became `weight = 0`, it would collapse the `NULL`≠`0` distinction the v0.6 explicit/implicit blend depends on (plan Risks).
